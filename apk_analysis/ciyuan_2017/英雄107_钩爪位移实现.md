# 英雄 107 弹射钩爪（3101/3103）的位移实现

问题：3101/3103 释放时的位移怎么实现的，当前包（`ciyuan_2017`）里有没有记载。

**结论：参数与引擎在包里，粘合脚本不在。**

- 3101/3103 本身**不是位移技能**——它们是钩爪发射，`NAssaultSpeed = 0`。
- 位移由 **3102「爪钩冲锋 type2」** 承担，走原生库的 **`AssaultMgr`（冲锋）系统**，`NAssaultSpeed = 10`。
- `AssaultMgr` 的**完整弹道实现**在客户端原生库里（含速度、加速度、上下重力、起止点、高度、服务端同步开关）。
- 但把"钩爪命中地形"接到"发起冲锋"上的**行为脚本（`.s`）在三个 APK 里都不存在**——`SBullet.StrScriptFile` 指向的路径全部落空。

## 四、服务端同步：`OnMsgPlayerAssaultSyncPos`

反汇编 `GameDuplicate::OnMsgPlayerAssaultSyncPos(Msg*)`（vaddr `0x2a2760`，292 字节）可见：

1. 先从消息偏移 4–7 拼出玩家 ID，调 `GameDuplicate::GetPlayerByID(uint)`；
2. 若该玩家 `[+0x560]` 处的标志非 0，直接返回（**不做同步**）；
3. 否则从偏移 0xb 起连续读取**多组 16 位有符号定点数**（`ldrb` 两两拼接后 `sxth` 符号扩展、`vcvt.f32.s32` 转浮点），即成对的坐标/向量；
4. 交给下游应用到 `AssaultMgr`。

这与之前查明的移动同步机制同源：**服务端下发定长量化坐标，客户端把它推进本地运动控制器**（对比 `onMsgPlayerVerifyPos` → `CMoveCtrl::PushPlayerVerify`）。所以钩爪冲锋的位置**由服务端裁定**，客户端只做插值与表现。

## 五、子弹定义：脚本路径在，脚本文件不在

`bulletdata_c.dat`（`SBullet`，153 条）中脚本路径归属 `profession 107` 的共 **4 个**：

| 子弹 ID | `StrModelFile` | `StrScriptFile` |
|---:|---|---|
| 2961 | `skill/107_sanli/s03_gouzhua/trace/tx_107_s03_3_01.x2` | `script/skill/107/bullet2961.s` |
| **2963** | **（无模型）** | `script/skill/107/bullet2963.s` |
| 2964 | （无模型） | `script/skill/107/bullet2964.s` |
| 2965 | `skill/107_sanli/s03_gouzhua/trace/tx_107_s03_3_04.x2` | `script/skill/107/bullet2965.s` |

**2963 没有模型但 `NDeadTimes = 800`**——一个不可见的判定用投射物，最符合"钩爪本体/拉拽判定"的角色（有存活时间、无可见模型）。

`bulletstatudata_c.dat`（同为 `SBullet`，133 条）补充了这 4 个子弹的状态参数：

| 子弹 ID | `NBulletStatu`（字符串） | `NIsRepeatedTar` | `NIsShareView` |
|---:|---|---:|---:|
| 2961 | `3;6` | 0.4 | 1 |
| **2963** | **`4;5`** | **2.1** | **6** |
| 2964 | `4;5` | 1.0 | 6 |
| 2965 | `9` | 0.6 | 5 |

`NBulletStatu` 是分号分隔的**字符串**（全表取值形如 `1;4`、`3;6`、`4;5`、`9`），说明它是子弹状态/行为标记列表，而非单个枚举——但每个数字的含义没有在包里给出。

## 六、关键缺口：**`.s` 脚本文件三个包都没有**

| 检查项 | moba_2016 | **ciyuan_2017** | game300_2018 |
|---|---:|---:|---:|
| APK 内 `.s` 文件数 | **0** | **0** | **0** |
| 路径含 `script/skill/` 的文件 | 0 | 1（`skillbtnmgr.lua`，弱匹配） | 3（均为 `skill*ui.lua`） |

也就是说 `SBullet.StrScriptFile` 指向的 `script/skill/107/bulletXXXX.s` **全部缺失**。

同时：

- `SSkill_SkillLevel.StrScript`（字段 76）在 **schema 中存在**，但 2017 的 2050 条记录中**一次都没填充**（2018 的 3276 条同样只填了 `NAssaultSpeed`）。所以 2017 也没有技能级 Lua 脚本。
- **技能表里没有任何字段引用子弹 ID**：`SSkill_SkillLevel` 与 `SSkill_Skillbase` 都没有 bullet 相关字段。因此"哪个技能发射哪个子弹"这条映射也不在客户端配置里。

## 七、能还原到哪一步

| 环节 | 是否在 `ciyuan_2017` 包内 | 载体 |
|---|---|---|
| 钩爪是技能、射程 16、耗气 9→7、CD 250ms | ✅ | `SSkill_SkillLevel` |
| 钩爪只打地形/建筑、命中后拉拽、可连续飞行 | ✅（文字） | 主表描述 |
| 位移是一次「冲锋」及其参数（速度 15、时长 5、`NAssaultSpeed` 10、跳跃开） | ✅ | `SSkill_SkillLevel`（3102） |
| 冲锋的弹道物理（加速、上下重力、起止点、高度） | ✅（代码） | `AssaultMgr` 符号 |
| 冲锋位置由服务端同步 | ✅（代码） | `OnMsgPlayerAssaultSyncPos` + `setSync` + `VerifyAssaultPos` |
| 子弹的模型、存活时间、状态标记、脚本**路径** | ✅ | `SBullet` 两张表 |
| **钩爪命中地形的判定与"命中后触发 3102 冲锋"的粘合逻辑** | ❌ | 应在 `.s` 脚本内（**缺失**）或服务端 |
| **`NBulletStatu` 各数字的含义** | ❌ | 未在包内定义 |
| **技能 → 子弹的绑定关系** | ❌ | 客户端配置无此字段 |

**因此：可以完整还原"位移的数学模型与同步方式"，但无法还原"钩爪如何判定命中地形、命中后如何触发这次冲锋"**——这部分要么在服务端，要么在未随包发布的 `.s` 行为脚本里。

## 九、未解

- **`.s` 脚本的格式未知**，且三个包都没有样本，无法判断它是 Lua 变体、自定义字节码还是文本。
- **`NBulletStatu` 的数字语义未知**（`4;5`、`3;6`、`9` 等）。
- **子弹 2961/2963/2964/2965 与技能 3101/3102/3103 的对应关系未能确认**：子弹 ID 与部分技能 ID 数值相同（2961、2964、2965 既是子弹又是技能），但这可能只是编号习惯，客户端没有任何字段建立此映射；2963 不对应任何技能 ID。
- **`NSpeicalSkillFlag` 的位含义未知**：3101/3103 = 11（1\|2\|8）、3102 = 1、2973 = 14（2\|4\|8）、2975 = 10（2\|8），未找到消费该字段的代码或注释。
- **3101 描述里的"10 气体值"与字段 `NCostDander = 9` 不一致**，且描述称"无冷却"而 `NCDTime = 250`——主表描述已被证实存在陈旧内容（见[战斗逻辑](英雄107_战斗逻辑.md)第五节），此处以字段为准。
