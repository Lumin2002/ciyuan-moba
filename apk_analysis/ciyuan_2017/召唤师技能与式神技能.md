# 召唤师技能与式神技能（`summonerskill_c.dat` 的误读与澄清）

调查"召唤师技能：恢复"时查清的一件事：**`summonerskill_c.dat` 不是召唤师技能表**，而是**召唤物（式神）技能表**。2017 包里没有召唤师技能的数据。

---

## 一、2017 包里的 `summonerskill_c.dat` 到底是什么

`ciyuan_2017/decoded/assets/data/conf/summonerskill_c.dat` → `SSummonerSkill`，**只有 3 个字段**：

| 字段号 | 名称 |
|---:|---|
| 1 | `UnLevel` |
| 2 | `UnSkillID` |
| 3 | `UnIsCountSkill` |

14 条记录，无名称、无消耗、无任何数值：

| `UnSkillID` | `UnLevel`（解锁等级） | `UnIsCountSkill` |
|---:|---:|---:|
| 8023 | 1 | 0 |
| 8024 | 1 | 0 |
| 8025 | 1 | 0 |
| 8026 | 1 | 0 |
| 8028 | 1 | 0 |
| 8029 | 1 | 0 |
| 8030 | 1 | 0 |
| 8039 | 1 | 0 |
| 8060 | 1 | 0 |
| 8031 | 2 | 0 |
| 8032 | 6 | 0 |
| 8033 | 7 | 0 |
| 8035 | 12 | 0 |
| 8059 | 35 | 0 |

**这 14 个 ID 在 2017 的技能表里完全不存在**：

- `skill_skillbase_c.dat` 共 605 个技能，ID 范围 **2841–34004**
- 其中 8000 段只有 29 个，全部是 `profession = 10001` 的**小兵/野怪/防御塔**：`8001–8021`（攻城兵、远程兵、炮车、超级兵、近战兵、大龙、小龙、泉水、野怪、毒液之池、尖刺打击…）与 `8091–8099`（防御塔攻击）
- **8022–8090 是一段空白**，`summonerskill_c.dat` 指向的 8023–8060 正落在这个空白里

## 二、为什么能确定它是"式神"而不是"召唤师技能"

三个包交叉比对后，**同一个 ID 段在 2018 包里被命名了**：

`game300_2018` 的 `skill_skillbase_c.dat` 中，8023–8033 全部存在且带名字，`profession = 10001`：

| ID | 2018 中的名称 |
|---:|---|
| 8023 | 式神狸猫攻击 |
| 8024 | 式神鼠妖攻击 |
| 8025 | 式神石怪攻击 |
| 8026 | 式神蛤蟆攻击 |
| 8028 | 式神蓝攻击 |
| 8029 | 式神妖狐攻击检测 |
| 8030 | 式神小鼠妖攻击 |
| 8031 | **式神狸猫回血** |
| 8032 | 式神红范围伤害 |
| 8033 | 式神妖狐攻击伤害 |

"式神"即**召唤物**。因此 `SSummonerSkill` 指的是"召唤者的**召唤物**技能"，不是"召唤师技能"。

且 2018 包里**另有一张真正的召唤师技能表**，编号体系完全不同：

`summonerskill_summonerskill_c.dat` → `SummonerSkill_SummonerSkill`（8 条，字段 `NID` / `SName` / `NMinLevel` / `NSkillID`）：

| NID | 名称 | 解锁等级 | 技能 ID |
|---:|---|---:|---:|
| 101 | 闪现 | 11 | 36001 |
| 102 | 疾跑 | 3 | 36002 |
| 103 | **治疗** | 1 | 36003 |
| 104 | 惩戒 | 9 | 36004 |
| 105 | 虚弱 | 5 | 36005 |
| 106 | 眩晕 | 7 | 36006 |
| 107 | 净化 | 3 | 36007 |
| 108 | 狂暴 | 5 | 36008 |

**2017 包里既没有这张表，也没有 36001–36008 这些技能**（2017 技能 ID 上限 34004）。所以 2017 的召唤师技能**在客户端里不存在**。

## 三、2018 包提供的可见数值（仅作参照）

`game300_2018` 的 `script/langtable/table/simple_chinese/skill.lua` 有这一节的原文注释就是 `--召唤师技能描述`：

| 技能 ID | 名称 | 描述（原文） | 冷却 |
|---:|---|---|---:|
| 36001 | 闪现 | 像目标方向闪烁一段距离 | 120 s |
| 36002 | 疾跑 | 移动速度增加 35%，持续 8s | 120 s |
| 36003 | **治疗** | **恢复自身和离自身最近一名队友的最大生命值 15% 的血量** | 120 s |
| 36004 | 惩戒 | 对非英雄的单位造成真实伤害，并回复少量的生命值 | 无 |
| 36005 | 虚弱 | 对周围敌方英雄施放，使目标造成的伤害减少 30%，持续 2.5s | 120 s |
| 36006 | 眩晕 | 对周围敌方英雄施放，使目标进入眩晕状态 0.8s | 120 s |
| 36007 | 净化 | 清除自身所有异常状态，并在接下来 2s 内不受任何控制 | 120 s |
| 36008 | 狂暴 | 增加自身 60% 的攻击速度，持续 6 秒 | 60 s |

冷却取自 `skill_skilllevel_c.dat` 的 `NCDTime`（`langtable` 里该字段为空）。

**注意两点**：

1. **这套数据属 2018 包，ID 体系与 2017 完全不同，不能迁移到 2017。**
2. **没有任何召唤师技能回复怒气**。"恢复/治疗"类只有 36003，效果是**最大生命值 15%**，与怒气无关（三笠的怒气回复来自英雄本身的被动，见下）。

## 四、2017 关于"恢复"的全部线索

翻遍 2017 包（55 张 `.dat` + 14 个明文 `.csv` + 164 个 Lua + `lang.txt` + 原生库原始字节），与"恢复/怒气"相关的内容只有这些：

| 位置 | 内容 | 说明 |
|---|---|---|
| `string_client_c.dat` | `eClinet_recovermedicine = 恢复` | 唯一的"恢复"名称键；**在 Lua 中无任何引用** |
| `string_client_c.dat` | `eClient_NpcTransmit = 传送` | 另一个疑似技能名键，同样未被引用 |
| `lang.txt` | `skill_costda=怒气`、`lack_angry=当前怒气值不足` | 怒气相关文案 |
| `gamedef.lua` | `Attr_SkillDander = 103 --怒气`、`eSkillPropertyType_Fury = 3 -----怒气` | 怒气属性与技能消耗类型 |
| `battle_data.lua` | `summerSkillNum = 2`、`tmp.summonSkillIds = {} -- 召唤师技能` | **2 个召唤师技能槽**，ID 由服务器下发 |
| 原生库 `.so` | `生命恢复 +%d/5s`、`法力恢复 +%d/5s` | 属性格式化模板，出现在属性面板文本中 |

**没有**：召唤师技能的名称表、图标资源、消耗/回复数值、对应的状态记录（`SSkill_StatusList` 的 1402 条中，名字含"恢复/治疗/怒气"的 **0 条**）。

`.so` 里 `召唤师技能`、`治疗`、`怒气` 三个词的 UTF-8 出现次数均为 **0**——注意 `native_core_strings.txt` 是用 ASCII 正则提取的，中文不在其中，所以本次直接搜索了二进制原始字节。

**结论**：2017 的召唤师技能只有"14 个 ID + 解锁等级 + 2 个槽位"这一层元数据，**技能效果（含恢复生命值/怒气值的数值）由服务端决定，不在客户端包内**。这与 2017 伤害公式同样落在服务端的结论一致。

## 五、顺带查清：`StrScroll` 是出装路线

英雄表 `SHero.StrScroll` 字段曾疑似召唤师技能（按名字 卷轴 猜测）。实测 35 个英雄：

```
101 黑岩射手  20076;20025;20008;20024
107 三笠      20076;20025;20008;20029
141 御坂美琴  20076;20025;20008;20024
（其余 32 个英雄同构）
```

**前 3 件恒定**（`20076 巨神峰之擎`、`20025 野性烈炎`、`20008 长剑`），**第 4 件随英雄定位变化**：`20024 灵巧披风`（暴击型，16 次）、`20016 魔抗斗篷`（5 次）、`20027 精魄之石`（3 次）、`20026 吸血鬼节杖`（2 次）、`20028 深渊权杖`/`20029 大天使之杖`/`20021 短剑`（各 1 次，法系/攻速系）。

全部为 20000 段基础装备，因此 `StrScroll` = **推荐出装路线**，与 `StrEquip`（成型装）、`StrSmartBuy`（购买顺序）并列，三个字段都不涉及召唤师技能。

## 六、复现

```bash
python apk_analysis/decode_config_tables.py summonerskill              # 2017 的 14 条元数据
python apk_analysis/decode_config_tables.py --slug=game300_2018 summonerskill summonerskill_summonerskill
```

2018 的名称与描述需读 `game300_2018/decoded/assets/data/script/langtable/table/simple_chinese/skill.lua`（UTF-8）与 `skill_skillbase_c.dat`。

## 七、未解

- **2017 的 14 个 `UnSkillID`（8023–8060）在 2017 客户端里没有定义**，无法确定它们在 2017 版本中是否真被使用（表里有记录 ≠ 运行时启用）。
- **2017 是否真的有"召唤师技能"这个系统**未能确认：`battle_data.lua` 的 `summonSkillIds` 注释写作"召唤师技能"，但客户端没有对应的名称与效果数据；它也可能指向别的系统（如式神或场内道具）。
- **`eClinet_recovermedicine = 恢复` 的用途未确认**：键名直译是"恢复药"，且无 Lua 引用，不能断定它就是召唤师技能"恢复"的名称。
