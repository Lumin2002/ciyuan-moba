# 伤害公式还原：2018 包给出了公式，2017 包没有

一次针对"能否还原伤害公式"的完整尝试。**结论是：2016 / 2017 两个包还原不了（数据里就没有），但 2018 包里有公式本体**——它是客户端 Lua 里一张按公式 ID 索引的分发表。

本文同时修正了 `ciyuan_2017` 专题报告早期的错误结论。

---

## 一、跨包审计：公式字段的填充情况

对三个包各自的 `skill_skilllevel_c.dat` 用**各自的 schema**（分别从 `libtombird.so` / `libgame.so` 恢复）解码后逐条核查：

| 字段 | schema 字段号 | moba_2016 (1403 条) | ciyuan_2017 (2050 条) | game300_2018 (3276 条) |
|---|---:|---:|---:|---:|
| `NFormulaID` | 20 | **0** | **0** | **3276** |
| `NGodFormulaID` | 21 | 0 | 0 | 0 |
| `NDamageCoefficientFirst` | 54 | **0** | **0** | **3276** |
| `NDamageCoefficientFirstSecond` | 55 | **0** | **0** | **3276** |
| `NDamageCoefficientFirstS` | 81 | **0** | **0** | **3276** |
| `NAttackRate` | 14 | 0 | 0 | 0 |
| `NHitAddons` | 15 | 0 | 0 | 0 |
| `NIfKeepAttack` | 32 | 0 | 0 | 0 |
| `NDamageType` | 82 | 1403 | 2050 | 3276 |

**为什么"0 次出现"等于"数据里没有"**：这个 protobuf 序列化器**显式写入零值**（2017 包 2050 条中有 1674 条含值为 0 的 `NCostMP`）。既然零值会写，字段完全不出现就只能是生成数据时没有该字段。

三个包的 `SSkill_SkillLevel` 字段号一致（2018 自查 1087 个字段全一致、0 冲突），所以这不是编号差异——**2018 的策划表新增并填充了公式相关列，2016/2017 没有**。

## 二、公式本体：客户端 Lua 的分发表

`game300_2018` 的 `assets/data/script/logic/ui/bat_skill_desc_ui.lua` 里有一张按公式 ID 索引的表 `BatSkillDescMgr.damageValueStringFunc`，被技能描述渲染调用：

```lua
-- bat_skill_desc_ui.lua:542-564
local nFormulaID, damageFirst, damageFirstS, damageFirstSecond = 0, 0, 0, 0
if valueType == 1 then
    nFormulaID         = JGameSkill_GetDemageFormulaID(valueID, skillLevel)
    damageFirst        = JGameSkill_GetDamageCoefficientFirst(valueID, skillLevel)
    damageFirstS       = JGameSkill_GetDamageCoefficientFirstS(valueID, skillLevel)
    damageFirstSecond  = JGameSkill_GetDamageCoefficientFirstSecond(valueID, skillLevel)
end
valueString = self.damageValueStringFunc[nFormulaID](map_category, damageFirst, damageFirstS,
                                                     damageFirstSecond, physicsAttack, magicAttack)
              .. self.damageTypeStringFunc[nFormulaID]()
```

战斗内取的是玩家当前属性：

```lua
physicsAttack = rolePlayer:GetAttribute(Attr_PhysicsAttackMax)   -- Attr 30
magicAttack   = rolePlayer:GetAttribute(Attr_MagicAttack)        -- Attr 31
```

### 2.1 三个系数的确切含义

从 `damageValueStringFunc` 的实现可以完全确定（以公式 `[1]` 为例）：

```lua
[1] = function (Map_category, DamageCoefficientFirst, DamageCoefficientFirstS,
                DamageCoefficientFirstSecond, physicsValue, magicValue)
    if not IsInBattleMap(Map_category) then
        return ...tostring(DamageCoefficientFirstSecond)..
               "(+"..DamageCoefficientFirst.."%"..EXTRA_PHYSICS_ATTACK_STR..")"...
    else
        return ...tostring(DamageCoefficientFirstSecond)..
               "(+"..tostring(math.floor(physicsValue * DamageCoefficientFirst * 0.01))..")"...
    end
end,
```

| 字段 | 含义 | 单位 |
|---|---|---|
| `NDamageCoefficientFirstSecond` | **固定基数**（描述里括号前的数字） | 点 |
| `NDamageCoefficientFirst` | **物理攻击百分比系数** | 百分数（100 = 100%） |
| `NDamageCoefficientFirstS` | **魔法强度百分比系数**（S = 法术） | 百分数 |

即伤害的基础形式为：

```
减免前伤害 = NDamageCoefficientFirstSecond + floor(攻击力 × NDamageCoefficientFirst  × 0.01)
                                        + floor(魔法强度 × NDamageCoefficientFirstS × 0.01)
```

**`NDamageCoefficientFirst*` 是百分数**这一点由数据分布佐证：取值几乎都是 5 的倍数，非零值里 100 最常见（`First` 共 41 种取值：0/100/60/50/80/30/70/90/40/20…）。

### 2.2 公式 ID 决定伤害类型与用哪套攻击力

| `NFormulaID` | 伤害类型（来自 `damageTypeStringFunc`） | 使用的攻击力 | 2018 数据中出现次数 |
|---:|---|---|---:|
| 1 | 物理 | 物攻 × `First` | 227 |
| 2 | 魔法 | 魔攻 × `First` | 496 |
| 5 | 物理 | 物攻 × `First` | 753 |
| 7 | **真实** | 物攻 × `First` + 魔攻 × `FirstS`（系数 ≤0 时退化为单边） | 36 |
| 8 | 物理 | 同 7 的双系数结构 | 0 |
| 9 | 魔法 | 同 7 的双系数结构 | 23 |
| 1008 | **生命回复** | 魔攻 × `First` | 93 |
| 2001 | 物理 | 物攻 × `First` | 16 |
| 2002 | 魔法 | 魔攻 × `First` | 0 |
| 2005 | 物理 | 物攻 × `First` | 24 |
| 2008 | 物理 | 双系数结构 | 0 |
| 2009 | 魔法 | 双系数结构 | 0 |
| **0** | **表中未定义** | — | 176 |
| **4** | **表中未定义** | — | 1432 |

### 2.3 一个必须说明的缺口：公式 0 和 4 没有实现

数据中使用最多的正是公式 **4（1432 次）**，加上公式 **0（176 次）**，而这两者在 `damageValueStringFunc` / `damageTypeStringFunc` 里**都没有对应函数**——如果真被调用会是 `attempt to call a nil value`。

看这两个 ID 落在哪些技能上：

- 公式 0：`被动`、`爪钩`、`地面冲锋`、`反弹治疗`、`冰之枪`——多为被动或位移
- 公式 4：`机枪模式`、`蓝羽化`、`真蓝羽化`、`腐烂开`、`腐烂关`、`羁绊之心`、`枪术专精`——**几乎全是形态切换 / 开关 / 被动类技能**

所以最可能的解释是：**公式 0 与 4 表示"该技能不产生直接伤害"**，这类技能的描述不会走伤害占位符分支，因此这张表不需要它们。我未能进一步证实（没有找到消费该字段的其它代码路径），此处标注为**推断**。

## 三、这套公式是不是服务端用的那套

**不能完全等同，但很可能是同一条公式的前半段。**

Lua 里这个函数只做 `固定基数 + 攻击力 × 系数`，**没有引用防御方任何属性**——不含护甲减免、暴击、增伤（Attr 95）、护甲穿透。因此它算出来的是**减免前伤害**，正是技能描述里展示的数字。

服务端在 `SSkillReply.NHurt` 里给出的是**结算后**的最终伤害。从"减免前"到 `NHurt` 之间的减免曲线，客户端依然没有：

| 环节 | 位置 | 依据 |
|---|---|---|
| 固定基数 + 攻击力 × 系数 | ✅ **2018 客户端 Lua** | `bat_skill_desc_ui.lua` |
| 物理/魔法/真实/回复 的类型选择 | ✅ **2018 客户端 Lua** | `damageTypeStringFunc` |
| **护甲减免曲线** | ❌ 服务端 | 客户端 Lua 中检索 `defence`/减免 相关**只找到 UI 文案与属性显示**，无计算 |
| 暴击、增伤、穿透的最终结算 | ❌ 服务端 | 同上 |
| 公式平衡版本 `UFormulaBalanceCounts` | ❌ 服务端 | 仅在 `SSkillReply` 下发 |

**对 `ciyuan_2017` 而言结论不变**：它既没有公式表也没有系数（第一节），所以 2017 的伤害依然无法从客户端还原。2018 的价值在于**给出了公式的形状与系数语义**——如果你要自己实现服务端，可以直接照这套结构来，只差一个减免曲线需要自行设定。

## 四、附带收获：属性 ID 枚举获得四重独立验证

`analyze_attributes.py` 从 `ciyuan_2017` 配置表的中文标签恢复出的属性 ID，在客户端 Lua 里找到了三处独立佐证：

| 属性 ID | 我从配置表恢复的含义 | 客户端 Lua 中的独立确认 | 出处 |
|---:|---|---|---|
| 30 | 物理攻击 | `Attr_PhysicsAttackMax = 30` | 2017 与 2018 的 `gamedef.lua` |
| 31 | 魔法强度 | `Attr_MagicAttack = 31` | 2018 `gamedef.lua` |
| 42 | 物理护甲 | `PhysicsDefence = 42` | 2018 `game/artifact/artifact_data.lua` |
| 44 | 魔法抗性 | `MagicDefence = 44` | 同上 |

四条属性、两种完全独立的方法（配置表中文标签 vs 客户端常量定义）结论一致，说明从标签反推枚举的方法是可靠的。

## 五、仍未解决

- **公式 0 / 4 的确切语义**（推断为"无直接伤害"）未证实。
- **护甲减免曲线**未知：客户端一处都没有，只能自行设定或实测拟合。
- **`NGodFormulaID`** 在三个包的数据里都是 0 次出现，从未被填充；2018 的 `.proto` 把它标注为 `[READ] server`（服务端专用），与"客户端不用"一致。
- **`NAttackRate` / `NHitAddons` / `NIfKeepAttack`** 三个字段在三个包中同样从未出现。
- **2018 的公式系数能否迁移到 2017**：三笠的普攻技能 ID 在三个包中都是 `2961`，但 2016/2017 的数值体系明显不同（见[英雄 107 档案](ciyuan_2017/英雄107_三笠.md)的跨包对比：2016 无成长、2018 护甲腰斩），**不能假定同一技能的系数在三包间通用**。
