# 引擎身份与平台：能不能在 GitHub 找到对应源码

由"根据代码能否在 GitHub 找到相关代码"这一问引发的调查。

**结论：找不到。** 引擎是商业自研的 **Snake 引擎**（`snake::CSnakeEngine` / `ISnakeEngine`），从未开源，GitHub 与 Gitee 上都没有它的源码，也没有这三款游戏的服务端。

但这次搜索有**两个有价值的副产品**：确认了引擎身份与真实架构，以及找到了 `.s` 脚本的执行者。

---

## 一、引擎身份：Snake

来自 `libgame.so` 的符号与调试字符串：

```
snake::CSnakeEngine::m_instance                       # 单例
snake::CSnakeEngine::DoScriptFile(const char*)        # 执行脚本文件
snake::CSnakeEngine::RegisterScriptCallback(const char*, void*)
ISnakeEngine                                          # 引擎接口
```

引擎命名空间是 **`snake`**，入口单例是 `snake::CSnakeEngine`，对外接口 `ISnakeEngine`。

同命名空间下的子系统（部分）：

| 类别 | 符号 |
|---|---|
| 渲染 | `snake::CRenderer`（`EnableVertexAttr`/`SetVertexAttrStreamVBO`）、`snake::CShader`（`addAttribute`/`AddVertexAttr`）、`CShaderLib` |
| 场景/模型 | `snake::CModelNode`（`CalcTransformMatrix`、`SnapShot`）、`CBehaviourMoveToTarget`、`KeyFrameInterpolator` / `LinearKeyFrameInterpolator` |
| 相机 | `snake::CCamera::BuildMatrix`、**`snake::CCamera::BuildPickRay`**（拾取射线——与钩爪"选中地形"直接相关） |
| 窗口 | `snake::CWindow`、`CSlideWnd`、`CAsciiFontAttrMgr` |
| 数学 | `snake::Vec2` / `Vec3` / `Matrix`、`SystemOfLinearEquationOfTwo` |
| 数据 | `snake::CDataChunkLoader` |
| 脚本 | `CSnakeEngine::DoScriptFile`、`RegisterScriptCallback` |
| Lua 绑定 | `snake::LuaGetNumberArgument`、`LuaGetStringArgument` |

## 二、真实架构（修正此前"Cocos2d-x + Lua"的粗略描述）

`CXWindowswLayer` 是两者的桥接层——它自己是一个 cocos2d-x 图层（实现 `ccTouchesBegan/Ended/Moved`、`ccKeyDown/Up`、`didAccelerate`、`update`、`draw`），内部托管 Snake 引擎：

```
CXWindowswLayer::init
 └─ CXWindowswLayer::InitEngine
     ├─ CShaderLib::It().LoadDefaultLib
     └─ InitLights
CXWindowswLayer::draw  → "Revalidate GL Res"
CXWindowswLayer::processMsg / processMsgImpl / OnMsgZipMsg
```

分层：

| 层 | 技术 | 职责 |
|---|---|---|
| 3D 渲染与场景 | **Snake 引擎**（`snake::`） | 渲染器、着色器、模型、相机、关键帧插值、拾取射线 |
| 2D / UI / 平台 | **cocos2d-x**（`cocos2d::`） | `CCLayer`、`CCNode`、`CCTableView`、`CCLuaEngine`、`CocosDenshion` |
| 桥接 | **`CXWindowswLayer`** | 承载 Snake、处理触摸/按键/消息 |
| 音频 | **FMOD Studio** | `.bank` |
| 配置与网络 | **protobuf** | `S*` 消息 |
| 游戏逻辑 | **Lua 5.1 / LuaJIT 2.0.1** | 经 `Script_*` / `JScript_*` 调 C++ |
| 引擎脚本 | **Snake 自有脚本** | `CSnakeEngine::DoScriptFile` |

### 平台证据：不只是 Android

调试字符串里明确区分了三个平台：

```
CXWindowswLayer::InitEngine: Android Platform MTD Load Asset Disable!!!
CXWindowswLayer::InitEngine: Android Or IOS Platform ForcePot Disable!!!
CXWindowswLayer::InitEngine: Windows Resolution: %f,%f,%f,%f
CXWindowswLayer::InitEngine: Windows DesignResolution: %f,%f
CXWindowswLayer::InitEngine: MRT Supportted
```

**引擎本身有 Windows 构建**（`Windows Resolution` / `Windows DesignResolution` 分支），类名 `CXWindowswLayer` 也带 "Windows"。这意味着这个引擎/游戏可能**存在 PC 版本**，而不只是这三个安卓包。

## 三、`.s` 脚本之谜有了解释

此前查明：`SBullet.StrScriptFile` 指向 `script/skill/107/bullet2961.s` 等文件，但**三个 APK 里 `.s` 文件数都是 0**（见[钩爪位移实现](ciyuan_2017/英雄107_钩爪位移实现.md)）。

现在有了执行者的线索：**`snake::CSnakeEngine::DoScriptFile(const char*)`** —— Snake 引擎自带一套脚本执行入口，配合 `RegisterScriptCallback` 注册回调。结合以下三点：

1. `.s` 扩展名、不是 `.lua`
2. 2017 的技能表 `StrScript` 字段 2050 条全部为空，Lua 里也没有任何子弹行为代码
3. 引擎提供 `DoScriptFile` + 回调注册

**推断（未证实）：`.s` 是 Snake 引擎自有脚本格式，由 `CSnakeEngine::DoScriptFile` 加载执行**，与 Lua 是两套并行的脚本系统。这也解释了为什么用 Lua 永远找不到钩爪的行为逻辑。

附带线索：`snake::CCamera::BuildPickRay` 说明引擎自带**拾取射线**能力，正是"钩爪只命中地形和建筑物"所需要的判定手段。

## 五、补充：按 `emagroup` 查找，确认了发行商身份

`emagroup` 是 SDK 与公司标识。用它检索同样**找不到代码**，但确认了这家公司是谁，并带出一条产品线关系。

### 5.1 公司 = 亿马联盟（EMA）

| 项 | 内容 |
|---|---|
| 中文名 | **亿马联盟**（英文简写 **EMA**） |
| 官网 | `http://www.emagroup.cn/`（**现已 DNS 失效**） |
| 成立 | 2013 年，中国**上海**（与签名证书 `L=Shanghai` 一致） |
| 业务 | 专注精品移动互联网游戏的**发行**集团公司 |
| 出品游戏 | **英灵召唤师**、**魔霸之王** |

来源：[高手游厂商页](https://www.gaoshouyou.com/company/3414.html)。"EMA" 即 `EMA_APP_ID`、`com.emagroup.sdk`、`O=Emagroup` 中的 EMA。

### 5.2 一条产品线关系：次元大作战 = 魔霸之王 2

2017 包的包名是 **`com.emagroup.mbzw2.emagroup`**——`mbzw2` 即"**魔霸之王2**"。而 2016 包是 `cn.emagroup.kom.baidu`（魔霸之王，百度渠道）。

这解释了此前几个无法归因的观测：

- 两包主入口类**都是 `com.emagroup.kom.Tombird`**
- 两包资源高度重合（1,704 个文件内容完全相同）
- 两包使用同一套 `MP:` 封装与同一把密钥

即 **《魔霸之王》(2016) → 《次元大作战》(2017) 是同一条产品线的两代**，由亿马联盟自己发行（`…mbzw2.emagroup` 是自有渠道包）。而《300大作战》(2018) 是 Jumpw 的产品（`com.jumpw.mobile300`），只在引擎与资源上沿袭。

## 六、为什么搜不到

1. **引擎是商业自研的、从未开源**，也没有泄露副本进入公开代码托管。
2. **这三款游戏都是商业产品**，服务端代码不会公开；国内这类代码通常在论坛/网盘流通，不在 GitHub/Gitee 这类可索引的平台上。
3. **仓库搜索只覆盖名称/描述/README**，不覆盖文件内容；按符号名找源码需要 code search，而它需要认证。

## 七、这次搜索的实际收获

虽然没有找到可复用的代码，但摸清了本项目一直缺失的一环——**引擎身份**：

- 此前把架构粗略描述为"Cocos2d-x + Lua"，实际上 **3D 部分是自研的 Snake 引擎**，cocos2d-x 只承担 2D/UI/平台宿主。
- 引擎带自己的脚本系统（`DoScriptFile`），这直接解释了 `.s` 文件的归属与"Lua 里找不到钩爪逻辑"的原因。
- 引擎有 **Windows 构建分支**，暗示存在 PC 版本，值得作为后续线索。
- `BuildPickRay` 证实引擎具备地形拾取能力，与钩爪的"只命中地形和建筑"机制吻合。
